# Repository instructions

Read `PROJECT.md` before changing domain data, historical interpretation, or product behavior.

## Interactive visual development

When UX, presentation, layout, imagery, or interaction is being discovered through human review, use the repository skill `developing-through-interactive-prototypes`.

Within that governed prototype cycle, make the smallest observable candidate directly, keep it uncommitted, and show it in the running browser before treating it as retained behavior. After explicit acceptance, derive appropriate acceptance evidence, implement the retained result cleanly, run full verification, and only then commit or push.

For non-visual changes and work outside the prototype boundary, follow the normal Superpowers workflow.
