# CB&Q 9245 NW2 Collection Card Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the researched EMD NW2, real CB&Q 9245 identity, and owner-confirmed BLI HO model as a reusable three-level collection card.

**Architecture:** Add historical-locomotive and source datasets alongside the existing prototype and collection datasets. Pure model helpers join those records into a detail view model; the existing detail renderer adds historical, collection-model, and source sections while the tree receives only one new fixed lane.

**Tech Stack:** HTML5, CSS, vanilla JavaScript ES modules, SVG, JSON, Node.js built-in test runner, Python standard-library HTTP server

**Spec:** `docs/superpowers/specs/2026-09-11-cbq-9245-nw2-card-design.md`

## Global Constraints

- Preserve Prototype → HistoricalLocomotive → CollectionItem separation.
- Derive `owned` only from `data/collection.json`; the NW2 prototype remains `historical_only`.
- Add no framework, dependency, backend, graph-engine redesign, unrelated prototype research, or downloaded image.
- Store unknown owner facts as `null` and omit them from the UI.
- Store research provenance in `data/sources.json` and reference it by stable IDs.
- Keep all six supplied source URLs; do not copy the conflicting American-Rails production total into locomotive data.
